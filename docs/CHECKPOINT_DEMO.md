# Демо на чекпоинт — что реально запускается

Всё проверено прогоном 2026-09-04. Команды копируются как есть, из корня репозитория.
Порядок подобран так, чтобы каждый следующий шаг отвечал на вопрос, который возникает
после предыдущего.

---

## 1. Гейт: «код не сломан» (~20 сек)

```bash
make gate
```

```
393 examples, 0 failures
103 files inspected, no offenses detected
детерминизм: источников случайности нет
```

Третья строка — не тест, а **статическая проверка**: в `lib/routing` и `lib/execution`
нет `rand`, `shuffle`, `sample`, `Time.now`. Стоит проговорить, что это отдельная цель
гейта, а не общие слова про детерминизм.

## 2. Валидатор организаторов: «вывод примут» (~20 сек)

```bash
make validate
```

```
✅ Пройдено: 29
❌ Ошибок:   0
⚠️  Предупр.: 0
```

Фраза для этого места: **гейт и валидатор — разные вещи. Гейт говорит «наш код не сломан»,
валидатор — «наш вывод примут». Зелёными должны быть оба.**

## 3. Побайтовый детерминизм (~15 сек)

```bash
make determinism
```

```
детерминизм: OK
```

Два прогона, `diff -q` по выходному файлу. Если кто-то спросит «а как вы гарантируете
воспроизводимость» — это ответ одной командой.

## 4. Семь стратегий одним флагом — главный номер (~2 мин)

```bash
bundle exec bin/route --help
```

```
--strategy NAME   Стратегия ранжирования: amount_range, conversion, count_share,
                  load, obligations, priority, volume_share
```

Дальше — один и тот же вход, семь разных распределений (count по провайдерам):

| `--strategy` | vipay | payflow | quickpay |
|---|---|---|---|
| `count_share` | 3 | 3 | 4 |
| `volume_share` | 4 | 3 | 3 |
| `priority` | 4 | 3 | 3 |
| `conversion` | 4 | 2 | 4 |
| `load` | **0** | 2 | **8** |
| `obligations` | **0** | 4 | 6 |
| `amount_range` | 3 | 4 | 3 |

```bash
bundle exec bin/route reference/data/operations_queue_10.json --strategy load --out-dir /tmp/load
```

Два места, где стоит задержаться:

- **`load` даёт vipay 0, quickpay 8** — не баг. vipay загружен 4/10, quickpay 1/15,
  стратегия честно давит на наименее загруженного. Это ровно тот пункт критериев, где
  «загрузка влияет на выбор между доступными, а не только проверяется достижение лимита».
- **`obligations` даёт vipay 0** — vipay подошёл к `daily_turnover_max`, стратегия его
  опускает. Тоже осознанное поведение, а не перекос.

**И главное:** валидатор проходит на всех семи — 29 ✅ / 0 ❌ для каждой. То есть смена
политики распределения не ломает hard-constraints. Это можно показать прямо в терминале,
если спросят.

## 5. Одна операция, три объяснения (~1 мин)

Самое убедительное для критерия «объяснимость». op_105, три разные стратегии, поле
`details` из выходного файла:

```
count_share  → vipay     count_share: vipay 4000/5=800 против quickpay 2500/3=833
conversion   → vipay     conversion: vipay 780‰ против quickpay 675‰
load         → quickpay  load: quickpay 1/15 против vipay 4/10
```

Тезис: **движок не пишет «выбран по стратегии», он пишет арифметику, которую судья может
пересчитать на бумаге.** Первая строка — делитель Сент-Лагю, вторая — наблюдаемая по
истории конверсия в промилле (не паспортная), третья — дробь загрузки.

## 6. Два предопределённых кейса (~40 сек)

```bash
cat out/routing_decisions_test.json
```

- **op_103** (150 000 ₽): vipay `skipped` — `150000 > limit_amount_max 100000`,
  payflow `skipped` — `150000 > limit_amount_max 50000`, quickpay `only_eligible_provider`.
- **op_107** (800 ₽): vipay и quickpay `skipped` — `800 < limit_amount_min 1000`,
  остаётся payflow.

Две операции, где маршрут предопределён данными, и в файле видно **почему** — с числами
с обеих сторон сравнения.

## 8. Отчёт (~1 мин)

```bash

```

Что показать пальцем:

- `distribution` — `share_pct` против `target_pct` и `deviation_pp` рядом;
- `projected_daily_utilization` — **payflow 99.6%** (2 988 800 из 3 000 000);
- `attempt_distribution` — наблюдаемая конверсия по попыткам этого прогона;
- `skip_reasons` — `bank_not_in_list` 8, `amount_exceeds_limit` 3, `amount_below_minimum` 2;
- `recommendations` — параметрические, а не наблюдения:
  `payflow: свободно 100 000 ₽ при среднем чеке 38 580 ₽ — снизить traffic_percentage 35 → 20`.

## 9. Час стопкода (~15 сек)

```bash

```

Одна команда кладёт оба файла с боевыми именами в корень репозитория. Стоит показать —
это снимает вопрос «а успеете ли вы за час».

## Чего показывать НЕ надо

Спросят — отвечаем честно, сами не поднимаем:

- **`config/routing.yml` не подключён к пайплайну.** Файл есть, схема валидируется
  (`spec/config/loader_spec.rb`), но `bin/route` его не читает. Стратегия сейчас
  переключается флагом, не конфигом. Если попросят «поменяйте правило в конфиге» —
  показать нечего, честно сказать, что это ближайшая задача.
- **Слоёв нет.** Есть `Routing::Layers::Base` с зафиксированным инвариантом и пустой
  список `layers: []` в конфиге. Комбинация стратегий поверх базовой пока не собирается.
- **`deviation_causes: []` и `benchmark` с `null`.** Структура в отчёте есть, логики нет.
- **`achievable_pct` в отчёте сейчас равен `target_pct`.** Перенормировка (`Routing::Achievable`)
  написана и покрыта тестами, но в сборку отчёта ещё не подключена. Про Target/Achievable/Actual
  рассказывать можно и нужно — но как про механизм, который считается, а не как про колонку,
  которая уже живёт в файле.
- **`volume_distribution` показывает `target_pct: 0`** — `volume_share_pct` в снапшоте
  провайдеров нет, это поле из списка «полезно добавить самим». Цель по объёму пока не задана.
