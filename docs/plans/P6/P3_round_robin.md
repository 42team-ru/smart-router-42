# П3 — стратегия round_robin (baseline для сравнения)

## Зачем

`docs/SCOPE.md` §4.7 обещает сравнение стратегий на одной очереди (round-robin против
нашего движка). В коде такой стратегии нет, а без неё сравнение из П4 не с чем строить.
Побочная выгода: реестр стратегий 7 → 8 без правок ядра — это ровно тот аргумент,
который жюри проверяет в критерии «можно добавлять новые правила без переработки
архитектуры».

## Файлы

- `lib/routing/strategies/round_robin.rb` — новый.
- `spec/routing/strategies/round_robin_spec.rb` — новый.
- `spec/routing/strategies_registry_spec.rb` — число зарегистрированных стратегий.
- `README.md` §7 — упоминание восьмой стратегии одной строкой.

## Контракт

Наследует `Routing::Strategies::Base`, регистрируется как `round_robin`
(`register('round_robin', RoundRobin)` в конце файла — как у остальных).

```ruby
def rank(candidates, operation, state)  # -> Array[Domain::Provider], перестановка candidates
def name = 'round_robin'
def explain(ranked, operation, state)   # -> String с числами
```

Механика, целочисленная и детерминированная:

1. `base = candidates.sort_by(&:name)` — стабильный порядок, не зависящий от порядка
   поступления и от обхода хеша.
2. `offset = state.total_count_units % base.size` — позиция берётся из состояния прогона,
   не из счётчика внутри объекта стратегии (объект стратегии обязан быть без памяти:
   иначе два вызова сравнения из П4 дадут разные результаты).
3. `ranked = base.rotate(offset)`.
4. `explain` — строка вида
   `round_robin: позиция 3 из 3 допустимых, первым payflow` (числа обязательны).

Ни `rand`, ни `shuffle`, ни `sample`, ни `Time.now`. `rank` обязан возвращать
перестановку входа: `Planner#validate_permutation!` это проверяет и уронит прогон.

## Готово когда

1. `bundle exec bin/route reference/data/operations_queue_10.json --strategy round_robin --out-dir /tmp/rr`
   отрабатывает без ошибок.
2. `ruby reference/scripts/validate_10.rb /tmp/rr/routing_decisions_test.json`
   → `Ошибок:   0` (детерминированные кейсы обязаны держаться и на baseline).
3. Два запуска п.1 подряд дают побайтово одинаковый файл:
   `diff` двух копий — пусто.
4. `Routing::Strategies.known.size == 8`, `round_robin` в списке.
5. `make gate` и `make validate` зелёные, боевой прогон не изменился:
   `diff out/routing_decisions_test.json routing_decisions_test.json` — пусто.

## Обязательные спеки

- `spec/routing/strategies/round_robin_spec.rb`: перестановка входа; ротация зависит
  только от `state.total_count_units`; два экземпляра стратегии при одинаковом
  состоянии дают одинаковый порядок; один экземпляр, вызванный дважды подряд при
  неизменном состоянии, даёт одинаковый порядок (проверка отсутствия внутренней памяти);
  `explain` содержит цифры; один кандидат — вырожденный случай без деления на ноль.
- `spec/routing/strategies_registry_spec.rb`: реестр знает восемь имён, и
  `--strategy round_robin` собирается через `Routing::Assembly`.

## Что может сломаться молча

| Риск | Чем ловится |
|---|---|
| Стратегия хранит счётчик внутри себя и «дрейфует» между прогонами сравнения | спек «два вызова при неизменном состоянии совпадают» |
| Порядок кандидатов приходит из отсева и меняется от снапшота — ротация становится непредсказуемой | сортировка по имени + спек на порядок |
| `base.size == 0` при пустом каскаде | `Planner` не вызывает стратегию на пустом множестве; спек на одного кандидата фиксирует границу |

## Что передать в П5/П6

Реестр стратегий вырос с 7 до 8: добавлена `round_robin` (`lib/routing/strategies/round_robin.rb`),
детерминированная круговая ротация без учёта веса/приоритета/загрузки — offset берётся из
`state.total_count_units`, кандидаты перед ротацией сортируются по имени. Служит baseline
для офлайн-сравнения стратегий (П4, `docs/SCOPE.md` §4.7). Ядро (`bin/route`, реестр) правок не
требует — новая стратегия подключается файлом каталога плюс строкой `strategy:` в конфиге
(CFG-3). Текст для README §7, одной строкой:

> Восьмая стратегия — `round_robin`: детерминированная круговая ротация (offset из состояния
> прогона), используется как baseline для офлайн-сравнения с боевой стратегией (см. отчёт, П4).
