## Что делаешь

lib/routing/selector.rb — выбор активной стратегии в рантайме по правилам из
конфига. Эксперт просил «уметь в рантайме подбирать наилучшие стратегии»;
отвечаем правилами, НЕ обучением (нейросети = дисквалификация, ML по минимуму).

Сегодня стратегия одна на весь прогон: Assembly.strategy строит её один раз,
Planner держит в @strategy. Селектор это меняет.

Сработавшее правило и его причина обязаны попасть в attempts — с числом, а не
словами. Предикаты только целочисленные (amount_gte: 1.5 -> ArgumentError).

## Критерий приёмки

Сквозной спек №9 из брифа — главный: прогон с config/examples/selector.yml на
публичной очереди даёт «Ошибок: 0», И минимум у одной операции selected_provider
отличается от дефолтного прогона. Иначе селектор ничего не решает, и это надо
увидеть, а не спрятать.

Плюс диагностика (спеки 6–8): неизвестный предикат -> ArgumentError с именем
ключа и списком допустимых; неизвестная стратегия в use: -> KeyError со списком
известных. Опечатка в конфиге обязана давать внятную ошибку, а не NoMethodError.

Граничные: strategy_selection: {} -> Static; rules: [] -> Static от default;
default отсутствует -> берётся config.strategy; пустой каскад -> селектор не
зовётся, сегмента нет.

Флаг --strategy при непустом strategy_selection перекрывает всё, и сегмент
селектора обязан сказать про переопределение (спек 10).

Боевой config/routing.yml НЕ ТРОГАЙ, добавляешь config/examples/selector.yml.
