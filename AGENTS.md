# AGENTS.md — правила работы над smart-routing-42

Общий файл для Claude Code, Codex и dsh. `CLAUDE.md` — симлинк на него.

## Что это за проект

Движок умного роутинга выплат для хакатона. На входе снапшот провайдеров и
очередь заявок, на выходе — два JSON-файла в корне репозитория и объяснение
каждого решения. Офлайн, без веба и без БД.

Границы работ — `docs/SCOPE.md`. Архитектура и форматы — `docs/ARCHITECTURE.md`.
Задачи с критериями приёмки — `docs/TASKS.md`. Алгоритмы — `docs/RESEARCH.md`.
Материалы организаторов — `reference/`.

## Раскладка репозитория

```
bin/route                 CLI, единственная точка входа
config/routing.yml        вся настройка поведения
lib/
  io/                     загрузка и валидация входных данных
  routing/                допуск, стратегии, слои, план маршрута
  execution/              проход по каскаду, исходы, состояние резервов
  state/                  счётчики провайдеров, наблюдаемая статистика
  reporting/              оба выходных файла
spec/                     RSpec
docs/                     проектные документы
reference/                данные и валидатор организаторов
routing_decisions_test.json   ← в корне, требование организаторов
routing_report_test.json      ← в корне, требование организаторов
```

## Определение готовности

Задача сделана, когда зелено и то, и другое:

```
make gate       # rspec + rubocop
make validate   # валидатор организаторов, 0 ошибок
```

`make validate` запускает `reference/scripts/validate_10.rb`. Он проверяет
структуру, покрытие очереди, четыре эталонных кейса и допустимость выбранного
провайдера. **Его вердикт важнее нашего мнения о правильности.**

## Инварианты предметной области

Это границы проектирования, а не пожелания. План или код, который их нарушает,
неверен независимо от элегантности.

**Детерминизм.** Два прогона одного входа обязаны давать побайтово одинаковый
выход. В `lib/routing` и `lib/execution` запрещены `rand`, `shuffle`, `sample`,
`Time.now`. Случайность заменяется хешем от seed и идентификаторов. Это ловится
гейтом.

**Целочисленная арифметика в решающем пути.** Дроби сравниваются перекрёстным
умножением, не приведением к float. Веса — в базисных пунктах.

**Причины отсева — дословно** из `reference/data/reference_decisions.json`.
Валидатор их сверяет. Своих формулировок не изобретаем.

**`decision` в `attempts` принимает только `selected` и `skipped`.** Любое другое
значение валидатор считает ошибкой структуры. Неудачная попытка кодируется как
`selected` плюс наши дополнительные поля.

**`selected_provider` обязан входить в множество допустимых по исходному
снапшоту.** Наши списания лимитов пул только сужают, поэтому безопасны.

**spacepayments — fallback по допуску, а не по исходу.** Подхватывает операцию,
для которой ни один внешний провайдер не прошёл hard-constraints. Не подхватывает
операцию, чей единственный допустимый провайдер отказал.

**Онлайн-обработка.** Заглядывать в будущие операции очереди запрещено:
эксперты ответили, что каждая операция получает свой снимок. Единственное
исключение — офлайн-оптимум (задача X-4), он считается постфактум и попадает
только в отчёт, никогда в принятие решений.

**Резерв, а не пост-фактум.** Счётчики закрепляются за провайдером в момент
попадания в каскад. `approved` — коммит, `rejected` — полный откат, `expired` —
резерв держится. Незакрытый резерв тихо ломает eligibility.

**Причина без числа не принимается.** Каждый `details` содержит конкретное
сравнение: «52000 > limit_amount_max 50000».

## Ограничения хакатона

- Большая часть логики — на Ruby, и она не должна быть фиктивной.
- **Нейросети внутри кода запрещены. Дисквалификация.** ML — по минимуму,
  эксперты просили алгоритмический вид решения.
- Rails, БД и очереди не нужны и баллов не дают. Если появится причина их
  завести — сначала спросить человека, а не заводить молча.
- Библиотеки не ограничены. Здравый смысл: лишняя зависимость ради одной
  функции — плохой размен, но запрета нет.

## Работа с документами

Приоритет при расхождении: `SCOPE.md` → `ARCHITECTURE.md` → `TASKS.md` →
остальное. Нашёл противоречие — назови его, не решай молча.

Документы писались быстро и местами расходятся между собой. Три FAIL подряд по
одной задаче — почти наверняка противоречие в постановке, а не баг в коде.
Это повод остановиться и позвать человека.
